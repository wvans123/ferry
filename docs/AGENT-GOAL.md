# 客户端 agent 的目标：按商业产品的标准

对标 Claude Code 和 Codex CLI：在一台受限的 Windows 公司电脑上，能当主力工具每天用。每一条都有能自动跑的检查（编号接着 GOAL.md 往下排），做完一条勾一条。

## 先回答三个"为什么"

| 现象 | 原因 | 归谁 |
|---|---|---|
| 它爱去读一些不知道在哪的配置文件 | pi 自带的系统提示里写着"你运行在 pi 里"，还列出了 pi 文档和示例的路径，并要求"读 pi 的文档要读全"；另外提示里有一句"可以查看 PI_* 环境变量"。模型看到这些就会去翻。**是 agent 的提示词引导的，最后是模型自己决定去读** | 客户端提示词，Ferry 负责改 |
| 让它看 GitHub，命令返回 `000` | `curl` 在**工作电脑上**执行，而工作电脑的命令行直接上外网会被公司网关挡住，连接没建立起来，curl 就打印 000。agent 现在也没有专门的"上网"工具 | 网络环境；Ferry 加联网工具 |
| 每个命令都要按回车选 Allow | 现在只有"每次都问"一种模式，没有"这类命令以后都允许"，也没有安全命令白名单 | 客户端权限，Ferry 负责改 |

## 目标清单

### A. 权限：该问的才问（参考 Claude Code 的权限模式、Codex 的审批策略）

| 编号 | 要求 | 怎么验收 |
|---|---|---|
| A1 | 四种模式，Shift+Tab 切换、底栏显示当前模式：**默认**（改文件、执行命令前问）、**自动改文件**（项目文件夹里的改动不问，命令照问）、**只读规划**（只能读和搜，先出方案）、**全部放行**（都不问，禁止目录照样拦） | 每种模式下同一组操作，问 / 不问 / 拦的结果符合表格 |
| A2 | 确认框四个选项：**允许这一次**、**以后都允许这类命令**（在这个项目里记住，比如 `git status` 开头的都放行）、**这次对话里改文件都不问**、**拒绝并告诉 agent 原因** | 选"以后都允许"后，同类命令不再问，重开 ferry 也不问 |
| A3 | 规则文件：允许 / 询问 / 禁止三张表，支持 `bash(git log*)`、`edit(src/**)` 这种写法；用户级（所有项目）和项目级两层，禁止优先 | 单元测试覆盖匹配和优先级 |
| A4 | 只读命令默认放行：`git status/diff/log`、`ls`、`dir`、`type`、`cat`、`rg`、`Get-ChildItem` 等，不带重定向和管道写文件时才算只读 | 这些命令不弹框；`ls > a.txt` 仍然要问 |
| A5 | 危险操作在任何非放行模式下都问，并标红：删除整个目录、`git push --force`、`git reset --hard`、格式化、`curl ... | sh` | 自动改文件模式下 `rm -rf` 仍然弹框 |
| A6 | 写项目文件夹以外的位置总要确认（Codex 的"工作区可写"边界） | 自动改文件模式下写 `C:\Windows\x` 仍然弹框 |
| A7 | `/permissions` 查看和删除记住的规则 | 能列出、能删 |

### B. 提示词和行为

| 编号 | 要求 | 怎么验收 |
|---|---|---|
| B1 | Ferry 自己的系统提示：不再提 pi、不列 pi 文档路径；说明它在 Windows 上、用什么 shell、今天几号、项目是不是 git 仓库 | 模型收到的系统提示里没有 `pi documentation`、`PI_*`，有操作系统和 shell |
| B2 | 告诉模型：工作电脑不能直接上外网，要查网页用联网工具，不要用 curl | 提示里有这条 |

### C. 联网：由服务端代为访问

工作电脑上不了外网，但能连到 Ferry 服务端，服务端所在的电脑能上网。Cursor 和 Claude Code 的"读网页"也是在服务端执行的。

| 编号 | 要求 | 怎么验收 |
|---|---|---|
| C1 | `web_fetch` 工具：给网址，服务端去取，转成纯文本或 Markdown 返回，限制大小 | 读一个测试网页，拿到正文 |
| C2 | `web_search` 工具：服务端去搜，返回标题、网址、摘要 | 返回结果列表 |
| C3 | 服务端管理页可开关联网，可设"只允许这些网站"；默认**关闭** | 关闭时工具返回明确说明 |
| C4 | 每次联网都记进调用记录（网址、大小，不记正文） | 管理页能看到 |

注意：这相当于让工作电脑经你的服务端访问外网，绕开了公司网关对这些网址的检查。开启前请确认公司规定允许；只开"允许的网站"白名单更稳妥。

### D. 浏览器

| 编号 | 要求 | 怎么验收 |
|---|---|---|
| D1 | 通过 pi 自带的 MCP 支持接入 [Playwright MCP](https://github.com/microsoft/playwright-mcp)，驱动工作电脑上**已经装好的 Edge**（不下载浏览器）：打开网页、点击、填表、截图读内容。安装包里带好，`ferry config set browser true` 打开 | 在测试页面上点按钮、读到结果 |
| D2 | 浏览器的每个动作和命令一样走权限规则 | 默认模式下点击前会问 |

浏览器走的是工作电脑自己的网络（和你平时用浏览器一样，会经过公司网关）；联网工具（C）走的是服务端的网络。两者用途不同。

## v0.11 的调整

- 联网工具默认在工作电脑上执行：和浏览器一样经过公司代理，网关的规则照样生效；遇到网关确认页时说明去哪确认，不绕过。服务端代办保留为选项（`ferry config set web server`）。
- 启动时遇到公司网关确认页：自动在浏览器打开，确认后继续（F37）。长期办法是请 IT 把服务端地址加入白名单。
- 跟着 pi 更新：每周自动检查、全部测试通过才发布（`.github/workflows/update-pi.yml`）；新增终端界面冒烟测试（F38），防止 pi 更新弄坏界面。
- 不换成 DeepSeek Harness：它还是开发预览版（会有不兼容改动），以网页和桌面界面为主，用官方 API 时默认上传会话记录。等出正式版再评估。

### 0.15.1

- 接着以前的对话（`/resume`、`ferry -c`、重开 ferry）时，服务端还存着的消息只发一个引用，不再整段重传。以前重开后第一轮要把整个会话一次传上去，大请求容易被公司网关挡住（403）。F47。
- 半路被挡时记到 `logs/blocked.log`（只有状态码、响应头和对方页面的开头，没有对话内容）；先按 64 KB 一块重试一次；只有确认是网关确认页时才打开浏览器。`ferry doctor --upload` 测多大的上传能通过。
- `?` 显示帮助；Ctrl+C 两秒内按两次退出（原来是半秒），第一次按会提示；两次 Esc 不再打开会话树。

### 0.15.2

- 实测：Claude 经 OpenAI 兼容中转时缓存命中为 0，一天 830 万输入 token 全按原价；同一天 GPT 经中转命中 91%。
- 服务端给中转后面的 Claude 请求加上 Anthropic 缓存标记（系统提示、最后一个工具、最后一条消息）；中转回 400/422 就去掉标记重发，并记住这个模型不再加。
- 用量统计认中转返回的 `cache_read_input_tokens` / `cache_creation_input_tokens`。
- 自定义服务商可以选"接口格式：Anthropic"（Claude 原生 /v1/messages）；"测试"会检查中转是否支持，并提示切换。

## v0.16.1：工作中插话

pi 原本就有"引导"：agent 干活时按 Enter，话排队，等这一步的工具都跑完再插进去。缺两样：不能立刻插话（长命令、长回答只能干等），插进去的话 agent 当成普通一句，常常照原计划往下做。

| 新增 | 说明 | 自测 |
|---|---|---|
| 立即插话 | 有话排队时，空行再按 Enter：正在写的回答马上停；正在跑的工具让它跑完，后面的工具调用不执行；然后把你的话当普通消息发出（/rewind 也能回到它） | F53 |
