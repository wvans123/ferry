# 服务端管理页的设计（v0.9）

v0.8 的管理页把配置文件原样搬到网页上，用的人得懂 TOML、记住接口地址和参数。这一版参考几个成熟项目重做。

## 参考了什么

| 项目 | 学到的 |
|---|---|
| [cursor-byok](https://github.com/leookun/cursor-byok) 桌面端 | 服务商预设（智谱、Kimi、DeepSeek、火山、MiniMax）带好地址和推荐模型，只差 Key；"获取模型"从接口读取模型列表；每个模型可单独测试；调用记录表 + 单次调用详情（可选的详细记录）；提示词按用途分开（agent / ask / plan / 摘要） |
| [CC Switch](https://github.com/farion1231/cc-switch) | 90 多个预设，选一个、填 Key、启用；提示词单独一页，用 Markdown 编辑后启用 |
| [CLIProxyAPI 管理中心](https://github.com/router-for-me/Cli-Proxy-API-Management-Center) | 侧边导航分页：概览、基础设置、服务商、用量、日志、配置编辑器；配置文件编辑放在最后，作为高级入口 |
| [cliproxyapi-dashboard](https://github.com/itsmylife44/cliproxyapi-dashboard) | "用结构化表单代替编辑 YAML"；初次使用有设置向导 |
| [New API](https://docs.newapi.ai/en/docs/guide/feature-guide) | 渠道（服务商）是管理的核心对象：测试、批量操作、自动禁用；日志带筛选 |

共同点：**服务商是核心对象，Key 是唯一必填项**；配置文件编辑退到"高级"；用量页只放能回答问题的数字；调用记录可以点开看详情。

## 页面结构

```
┌ 顶栏：Ferry 服务端 · 运行中 · 版本                      [停止] ┐
├ 左侧导航 ┬──────────────────────────────────────────────────────┤
│ 概览     │ 连接卡片（登录命令一键复制）+ 流量图 + 一行摘要       │
│ 服务商   │ 已添加的服务商卡片；[+ 添加服务商] → 选预设 → 填 Key  │
│          │ → 自动获取模型列表 → 勾选要用的模型 → 保存并测试       │
│          │ 默认模型 / 摘要模型 / 工作电脑能否自选：三个下拉框      │
│ 提示词   │ 全局提示词、按项目的提示词、写摘要时的要求、最近一次   │
│          │ 发给模型的系统提示预览（开启详细记录时）              │
│ 脱敏     │ 敏感词列表（一行一个）+ 内置规则开关（内网 IP、邮箱、 │
│          │ 手机号）+ 试一试（输入一段文字看替换结果）            │
│ 调用记录 │ 表格 + 筛选；点一行看详情                             │
│ 设置     │ 外网地址、会话保存、请求上限、详细记录、开机启动、令牌│
│          │ 高级：直接编辑 models.toml                            │
└──────────┴──────────────────────────────────────────────────────┘
```

## 关键决定

1. **服务商 = 地址 + Key + 一组模型。** `models.toml` 增加 `[providers.*]`，模型通过 `provider = "deepseek"` 引用，不再每个模型重复写地址和 Key。旧写法（模型自带 `base_url`、`api_key_env`）继续支持。
2. **Key 填在网页里，存在服务端数据目录的 `secrets.toml`**（只有当前用户可读），不进 `models.toml`，也不会出现在任何接口的返回里（只返回末 4 位）。环境变量里有 Key 的照样能用，优先级更高。
3. **预设只写能确定的东西**：地址、拿 Key 的地方、少量推荐模型。模型名经常变，所以添加时总是先从服务商的 `/models` 接口读一遍真实列表，推荐模型只用来默认勾选。
4. **地址支持两种写法**：基础地址（自动加 `/chat/completions`），或者完整请求地址（以 `/chat/completions` 结尾的原样使用）。有些服务商的编程套餐路径不规则，需要后者。
5. **提示词分层**：工作电脑上 agent 自带的系统提示（含工具说明）不动；服务端的提示词追加在后面。分三种：全局、按项目（项目名 = 工作电脑上的文件夹名，从调用记录里自动列出来）、写摘要时的要求。
6. **概览只回答三个问题**：服务端正常吗、工作电脑怎么连、最近有没有在用。流量图保留，数字只留一行。
7. **详细记录默认关闭**：打开后在内存里保留最近 20 次请求的系统提示和最后一条用户消息（脱敏后的样子），用于检查提示词有没有生效；不写磁盘，重启就没了。
